# Dormant CH brief search publication

Directory title/short-summary documents and legacy derived brief features have separate authorities and tables. Neither is a transcript event; ordinary transcript reconciliation must not delete them.

## Directory metadata keyword documents

Migration `20261105024000` creates a per-tenant locked epoch/watermark, source row trigger, bounded server-owned reconciliation cursor and nonce/epoch/hash/deadline-fenced outbox. The source is the effective session_directory title/short_summary and authoritative event timestamps/project marker. An exact metadata authority RPC is available only to session_directory_search_worker; publication functions are service_role-only. No direct outbox privileges are granted. Applying the migration leaves the trigger off and creates no scope/outbox rows. The database owner enables or disables capture with `sessions.set_session_brief_documents_live(boolean)`; either state transition resets scope readiness, so the bounded backfill must complete again before authority can be complete. Its second phase publishes tombstones for keys deleted while capture was off. Dirty or uninitialized metadata refuses completeness, including an empty candidate pool.

The portable publishBriefDocumentsOnce stage uses the existing reviewed CH HTTP/JSONEachRow codec. Apply briefDocumentSchemaStatements with the approved operator identity first. Default runtime behavior is unchanged: this PR creates no client, resource, scheduler or enable flag. Runtime integration must explicitly invoke the stage under the separately reviewed backend identity. Exact-head review and operator credential/configuration/DDL changes remain separate gates.

## Legacy semantic features

session_brief_features stores existing legacy title, description, completion timestamp, vector and model faithfully; directory documents do not substitute their timestamps or text. Shared source API is generated byte-for-byte from RHC PR289 migration0076/API. Regenerate/check with bun scripts/sync-search-feature-source.ts --source <RHC-worktree> [--check]. Event and brief consumers must share that source API and have independent durable checkpoints. Do not query base tables directly from a copier or from request search.

copyBriefFeaturePage executes one bounded initial or journal page and returns the next state only after durable CH acknowledgement and a source CAS recheck. Initial backfill captures committed H, uses version2\*H+1 and replays the journal after H. Journal publication uses current source revision/hash; higher tombstones protect against delayed baselines and old erasers. The caller must claim a durable per-kind lease, persist returned state with nonce/generation/expiry CAS, and publish its committed readiness to CH. This PR does not implement that runtime state store: it is an explicit integration gate, not an in-memory completion claim. Search requires complete baseline, a completed journal poll, no known backlog and unexpired freshness; CH publication identity must remain stable across a query.

Brief query pools also require an audited CH-only exact event-visibility subquery applying the original event filters and snapshot, including unembedded events, before the1000-row brief cap. Directory min/max/project summaries and sparse event vectors cannot establish arbitrary event EXISTS. Operational all-event coverage and this subquery remain integration gates. Actual keyword pools preserve legacy ILIKE wildcard semantics and completion ordering; semantic uses cosine and completion order. Query embedding remains the existing configured provider. No keyword-only acceptance is assumed.

## Erasure, rollback and proof limits

Both publishers insert blank tombstones, then delete only exact scoped lower versions. An older eraser cannot remove a newer resurrection. A failed CH acknowledgement or source CAS leaves the durable cursor/ACK unchanged. Stop backend selection and publication before rollback; retain monotonic epochs/journal/tombstones while older CH versions exist. Do not reset source clocks or truncate derived state in place.

Synthetic evidence includes PGlite auth/claim/backfill/currentness/erasure tests, actual PostgreSQL17+pgvector journal races, and actual CH26 codec/vector refresh/clear/resurrection/source-CAS/HTTP-pool checks. The HTTP query proof uses an explicit synthetic event-visibility table and synthetic readiness port; it does not prove deployed all-event coverage, a real durable runtime store, live vector coverage/freshness, provider usability or four-pool caller parity. No production credentials, DDL, grants, deployment or flag changes were used.

Legacy keyword publication also carries PostgreSQL-computed lower(title/description). Native CH ILIKE and JavaScript lowercase are not equivalent to the source locale: actual disposable en_US.utf8/libc PostgreSQL17 vs CH26 disagrees on dotted-I, and Node24 scalar lowercase differs on55 newer Unicode mappings. readLegacyCasefoldProfile exports source scalar mappings in bounded8192-codepoint readonly metadata queries. Publish the verified source profile/hash alongside durable CH readiness; keyword queries require that exact hash-paired fold map and use case-sensitive CH LIKE on source-folded text. The extractor currently admits libc collation only and refuses contextual/non-simple mappings. Actual deployed collation/provider and profile integrity are activation evidence, not assumed from the synthetic image. Semantic vector queries do not require text case folding.

Before the FIRST baseline write, runtime must read the committed H from the generated journal API and durably CAS-initialize it under the lease. The portable cycle refuses baselineH=NULL. Recapturing H after a partial baseline crash can skip an intervening tombstone for a key already written to CH; a returned in-memory H is not durable initialization.

Current source authority also binds all16source column collations to DEFAULT/provider-d and requires every API-read relation to have RLS/FORCE-RLS disabled. The generated catalog hash joins API+SQL in source identity. A recent ledger marker cannot bless hidden base rows or custom source collation.

Source API pages have a server-side16MiB aggregate JSON fence (snapshot,baseline,journal); overflow sends only a small explicit error envelope and raises page_bytes. Retry smaller batches under the same durable H/lease; do not skip a row or advance a checkpoint. Actual builtinPG17 proof shows a17MiB projected title transfers only a39byte refusal packet. The Node stage's own per-row admission remains a separate gate.
