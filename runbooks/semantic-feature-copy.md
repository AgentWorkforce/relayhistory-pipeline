# Durable global search feature copier (dormant)

This adds the missing runtime behind the dense event/brief source API. It copies existing features; it never requests embeddings or models. Metadata Supabase contains source identity, profile, leases and per-kind checkpoints; feature payloads remain in new ClickHouse tables.

The global configured source ID owns two independent checkpoints, event and brief. These are not workspace cursors. Each baseline captures the source committed high-water H and persists it under a nonce/generation lease before writing a feature. A crash keeps H and the last committed cursor. Baseline completion alone is incomplete: a journal poll must reach the latest verified committed revision. Final source verification may discover a newer revision and keeps authority incomplete until caught up. Decimal source clocks remain strings/BigInt.

Every claim acknowledges a newer dirty CH authority before feature writes. Dirty version is2*g and final version2*g+1. SQL checkpoints advance only after the real stage's synchronous feature writes, required lower-version cleanup ACK and post-source CAS. Final authority follows SQL checkpoint CAS; a failed final publication leaves the CH dirty generation. An older late final cannot override a newer dirty generation. Final authority freshness is bounded by the current lease and source verification; SQL rechecks actual wall clock after blocked writes and rolls back an expired operation. Heartbeats cannot revive an expired old lease.

Source identity binds generated RHC API,0076 SQL and live catalog authority. The runtime verifies actual migration ledger checksum, proc bodies/configuration, triggers/view, DEFAULT column collations, source database locale and disabled RLS on every source relation. The committed generated manifest is not installation proof. Runtime additionally refuses elevated/INHERIT source roles, effective source table/column writes (PUBLIC included), and EXECUTE on reviewed SECURITY DEFINER mutators. No source owner fallback is allowed.

The actual target profile is PG17.11 builtin C.UTF-8, with datcollate,datctype,datlocale all C.UTF-8 and provider b. Profile extraction produced1433 scalar mappings in the owned proof; the exact map and source metadata hash are published in CH. Request-time readers never call Neon for casefold. libc c remains separately supported with empty datlocale. The pure protocol checks all bindings and hashes. Both authorities must be current and cover their maximum observed source clock. Consumers recheck both after queries/hydration; cursor identity uses the stable source/API/target/profile binding, preserving frozen-rank continuation across unrelated writes.

A new identity may adopt only a genuinely empty/new target. Existing feature rows (including higher-version rows), a different profile/source binding, and an advanced durable checkpoint with no target binding refuse. A new source clock may not silently reuse previous rows. Target hash binds actual normalized endpoint, database and exact generated event/brief schema protocols.

## Runtime integration

The existing Node session-pipeline Lambda accepts the explicit semanticCopy event. It runs only with SESSION_SEMANTIC_COPY_ENABLED=1 and SESSION_SEARCH_FEATURE_SOURCE_ID set. The existing Alchemy stack has a separate semantic schedule/permission pair, disabled by default, one minute cadence when separately authorized. Permission is restricted to the exact rule/account; phase planning rejects unrelated changes and mixed phases.

Portable entry: src/search-features/semantic-copy-main.ts. Default-off startup opens no client or credential. It reads the existing approved PipelineSecret shape from SESSION_PIPELINE_SECRET_JSON in memory: hoopdb_url, clickhouse {url,user,password,database}, and the optional analysis_source_readonly_url already introduced for analysis publication. It closes pools on exit and handles SIGTERM/SIGINT. No credential file is written. The bounded job alternates kinds, isolates one kind's failure, uses120s leases/30s heartbeat, at most20 pages of200 per tick and240s deadline. Source statement timeout15s. Server-side page_bytes overflow retries smaller batches under the same H/lease down to1; one oversized source feature fails closed. Source/API and event row bounds remain16MiB. Worker limits are unchanged.

Operational prerequisites before execution remain explicit:

- Apply the reviewed final RHC0076 authority and grant the existing separate readonly principal USAGE sessions, SELECT on the six source data/clock/view relations plus SELECT(name,checksum) on sessions.__migrations, and EXECUTE only on the six reviewed invoker helper functions needed by source reads. Verify its live permissions; the present source role may not yet have these new grants. No source role or grant was created outside synthetic owned containers here.
- Apply100000 through the authoritative pipeline migrator, including its ACL/boundary/sentinel update. Backend connection must have EXECUTE on its six backend RPCs; table access remains revoked. Do not assume an arbitrary existing hoopdb_url principal has these rights.
- Operator-create the four new CH schemas/tables from the committed schema functions in a fresh namespace, then review SELECT/INSERT and the stage's bounded ALTER DELETE privileges. No runtime DDL or automatic rebuild occurs.
- Configure exact source ID, target endpoint/database and generated schema hashes in the CH-only RHC/Worker consumer. The same actual CH endpoint/profile bindings must match.
- Existing Lambda SecretsManager access is reused without widening IAM. The separate compute-only EC2 runner has no app credentials or app policy; root must separately review any secret transport/DB/CH connectivity before invoking this portable entry. No .env or secret JSON file.
- The one-minute schedule and120s freshness bound are configured targets, not proven production SLA. Continuous portable invocation can drain baseline pages; production load/latency/backlog measurements and lease/authority monitoring are required. The30s retry delay does not imply the one-minute scheduler executes every30s. This proof does not establish full corpus completion time.
- Source coverage after DELIVERY_FORWARD/canonical S3 writes is separately unproved: a correct legacy source journal cannot certify writes bypassing that journal. Keep that activation gate explicit.

This replacement authority has no dependency on old runTail, tail_watermark, needs_full, transcript_events retention or unrelated legacy cleanup. The real proof contains only session_event_features,session_brief_features,session_feature_copy_authority,session_feature_copy_profiles.
