## Authority and metadata

Admission now has SIX owner-only fields:
org_id, privacy_baseline_sha256, retention_contract_sha256, schema_generation,
valid_until, control_epoch. control_epoch is the lowerhex64 global owner-held
Neon0077 epoch. It has no default or caller-adoption path. Existing five-column
inserts fail; existing populated admissions require separately reviewed owner
preparation before this append can add its NOT NULL column. There are no deployed
buffered admissions assumed by this source. Do not guess an epoch or auto-reopen
a halted source.

The private HMAC identity may carry:
```json
{"control":{"epoch":"<64 lowercase hex>","version":"<positive BIGINT decimal string>","digest":"<64 lowercase hex>","kind":"selection"}}
```
kind is selection or reset. The original HTTP bodies remain unchanged and reject
a body-supplied control. Versions remain strings through identity, JSON, adapter,
PostgreSQL and ACK; no Number conversion is permitted. The source first intent
is version1 for each epoch/(org,workspace,user), with target initial version0.

Source PostgreSQL computes the digest of UTF8 bytes of:
```sql
jsonb_build_array('delivery-cutover-control-v1',
  epoch,org,workspace,user,kind,payload)::text
```
using SHA256/hex. Selection payload is the original ordered array of
{source,session_id} objects plus origin_id and enabled; reset payload is request_id.
Account identity is separately verified. The target recomputes that same PG
expression from validated fields; no hand-written JS canonical serializer is used.

ingest_control_receipts stores only scoped version/digest/kind/result counts and
schema generation, not transcript content or the selection payload. It is
append-only through the runtime; the ingest role has no table access. Every
control first SHARE-locks exact current compiled PASS and matching active
admission/epoch, then takes the existing USER fence lock. A contiguous next version
applies the old selection/reset semantics and records its receipt atomically.
The exact current tuple replays; an exact known lower tuple returns stale without
mutation. Conflicting digest/kind, foreign epoch, gaps or unknown stale history
refuse. Final admission clock validation rolls back changes on expiry.

Private target ACK retains updated:true or reset:true/deleted:number, plus exact
requested control fields and outcome applied/replay/stale. The adapter validates
the tuple and outcome; deleted count is not completion evidence. The public RHC
response retains its old shape. The source completes only its matching pending
head; an old completion cannot clear a later pending operation. A current source
pending head cannot be cleared merely by a target stale result.

## Release and rollback gates

The same existing JSONB RPC signatures and ACLs are retained. Only genuinely
unenrolled legacy orgs keep unversioned calls. Enrolled/history-buffered orgs
refuse missing versioned controls. Ordinary canonical publication remains held.
040600 publisher changes to fanout/commit guards are independent and must be
composed without weakening them.

Close by retained admission UPDATE, never DELETE. Closing waits producer/control
SHARE locks; new operations refuse. Pending source controls still need explicit
reconciliation and durable retry. Keep GC running while draining/retiring buffered
bytes. No automatic epoch rotation or missing-history adoption is provided.
Recovery must preserve the control receipt ledger consistently with its fences.

Build/redeploy Worker and permanent GC with the FINAL combined compiled generation
and all four pure verifier assets. Old deployments must503 while generations
differ. Re-run final combined boundary generators, role/profile checks, actual
caller/target tests and retention/backlog gates. This source does not provision
IAM/KMS, secrets, schemas, admission or routing.
