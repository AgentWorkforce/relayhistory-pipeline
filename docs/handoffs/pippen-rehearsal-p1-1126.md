## The shared state bucket: validate-only

`stacks/aws/state-bucket.ts` `ensurePippenStateBucket` creates the sandbox's state bucket and
converges its versioning, encryption, public access block, ownership controls and tags bucket-wide,
even when it exists. Every stage in the account shares that bucket, so a per-stage prefix cannot
bound it. Hence:

- The stage input `pippenSandbox.stateBucket: "validate-only"` is **required** for
  `aws-rehearse-p1-1126` (and any stage later declared in `VALIDATE_ONLY_STAGES`), which may never
  run without it; only declared stages may set it, and `aws-proof-sandbox` may not. Every other
  stage (the proof stage, a fresh-account sandbox such as `aws-proof`, production) keeps its path
  exactly as before.
- In that mode the state layer (`stacks/aws/alchemy.aws.run.ts`) and `96bulls plan --capture`
  (`src/cli/aws-provenance-io.ts`) call `assertValidateOnlyState` instead: the caller must be this
  stage's lease session, the prefix exactly this stage's, and the bucket must already be in shape.
  Only reads: `sts:GetCallerIdentity`, `GetBucketVersioning` (it also answers NoSuchBucket),
  `GetBucketEncryption`, `GetPublicAccessBlock`, `GetBucketOwnershipControls`, `GetBucketTagging`.
  Never CreateBucket, never any Put. `HeadBucket` is not used: it needs `s3:ListBucket` without an
  `s3:prefix` condition, which would let the lease list every stage's keys.
- Expected settings: versioning `Enabled`; one SSE rule, `AES256`, no KMS key, bucket key off; all
  four public access blocks on; `BucketOwnerEnforced`; tags `pippen:sandbox=true` and
  `96bulls:component=alchemy-state` (the `96bulls:stack` tag names the stage that made it, so it is
  not required).
- Refusals carry fixed codes and no CLI text: `state_bucket_absent`, `state_bucket_unreadable`,
  `state_bucket_versioning_drift`, `state_bucket_encryption_drift`,
  `state_bucket_public_access_drift`, `state_bucket_ownership_drift`, `state_bucket_tagging_drift`,
  `state_prefix_mismatch`, `state_caller_mismatch`. If the bucket is absent or drifted, the
  rehearsal stops; the proof stage (or an operator) fixes the bucket, never this stage.

## Teardown (this stage's state only)

`bun scripts/rehearsal-state-teardown.ts` lists (dry run) and, with `--execute`, deletes every
object version and delete marker under exactly `96bulls/96bulls-aws/aws-rehearse-p1-1126/`
(`ListObjectVersions` with `--prefix` and key/version markers, then `DeleteObjects` by key and
version id, 1000 per call). It checks the caller and the bucket first, and refuses before deleting
anything if any listed key is outside the prefix (`state_teardown_outside_prefix`: a sibling stage,
`aws-rehearse-p1-1126x/`, a parent key, the prefix itself). It never deletes or changes the bucket.
The stage's v2 resources are removed by `alchemy destroy` for the stage (or the pippen sweeper)
before the state is torn down.

## Lease actions

The policy (`docs/handoffs/pippen-rehearsal-p1-1126.lease-policy.json`):

- State: `s3:ListBucket` and `s3:ListBucketVersions` only with `s3:prefix` like the stage prefix;
  `s3:GetObject`, `GetObjectVersion`, `PutObject`, `DeleteObject`, `DeleteObjectVersion` only on
  `<bucket>/96bulls/96bulls-aws/aws-rehearse-p1-1126/*`; the bucket's five settings readable.
- Explicit Deny: `s3:CreateBucket`, `s3:PutBucket*`, `s3:DeleteBucket*`,
  `s3:PutEncryptionConfiguration`, `s3:PutBucketVersioning`, `s3:PutBucketPublicAccessBlock`,
  `s3:PutBucketOwnershipControls`, `s3:PutBucketTagging`, lifecycle, policy and ACL writes on any
  `pippen-sbx-alchemy-state-*` bucket; listing with any other prefix; object reads, writes and
  deletes anywhere but the stage prefix and the stage's own `96bulls-aws-rehearse-p1-1126-*` buckets.
- v2 resources, only `96bulls-aws-rehearse-p1-1126-*` in `us-west-2` and `<account>`: SQS queue
  lifecycle and messaging, the function (create, update, permissions, tags, invoke), event source
  mappings only on that function (`lambda:FunctionArn` condition), EventBridge rules, CloudWatch
  alarms, the function's log group, and the secret path `96bulls/aws-rehearse-p1-1126/*`; list
  calls that cannot be scoped (`sqs:ListQueues`, `cloudwatch:DescribeAlarms`,
  `logs:DescribeLogGroups`, `events:ListRules`).
- Deny every non-IAM/STS/S3 call outside `us-west-2`, and everything after the expiry.

## Not covered (blockers before the rehearsal can run)

- **The stack cannot render the pipeline for this stage yet.** The session pipeline (and so the
  search split) is declared only inside the production transcript store, which is pinned to
  `aws-sessions-prod` (`stacks/aws/transcript-store.ts`). A non-prod stage that declares it is new
  work.
- **The proof account pin.** `stacks/aws/inputs.ts` `assertPippenProofSandbox` lets only
  `aws-proof-sandbox` target the proof sandbox's account. If the rehearsal uses that account, the
  pin must be widened by an owner decision; this branch does not change it.
- **The function's execution role.** Alchemy names and creates the Lambda role itself
  (`96bulls-aws-session-pipeline-<stage>-<suffix>`, path `/`, no boundary), which matches neither
  `96bulls-aws-rehearse-p1-1126-*` nor the sandbox's `/pippen/workload/` boundary rule. The lease
  grants no IAM role actions; how the role is made in the sandbox needs a decision.
- The lease policy is a document and a generator; attaching it is the lease issuer's step.
