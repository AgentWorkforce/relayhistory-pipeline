## Gate result: FAILS (one consumer cannot be classified)

The relayhistory-cloud #226 direct table reads use the static `SESSION_READS_TOKEN`.
Its PostgreSQL role is not pinned anywhere in code or config: it could be `service_role`
(bypasses RLS and keeps every column), `authenticated` (column grant plus RLS), or a
dedicated reader role. The revoke plan depends on it, so this consumer is UNCLASSIFIED
until the #226 owner pins it. Every other consumer is classified below.

## What this decides

- **Only #226 (rows 1, 3, 4, 5) reads the directory surface directly in production.**
  Everything user-facing (rows 6 to 8) reaches Supabase only through #226.
- **#226 already sends `projectContains` as a direct `project_id=ilike` when there is no
  `q` or agent prefix (row 1).** That is the RLS Seq Scan surface. The RPC already takes
  `p_project_contains` and every other row 1 filter, so the replacement for rows 1 and 3 is
  the existing RPC (detail through `p_session_id`), plus `short_summary` for free. Row 3
  needs the RPC's `p_session_id` without a workspace, which the RPC supports.
- **Rows 4 and 5 are not directory reads the RPC can replace today.** Pointers live on
  `session_index`, and the rollout marker on its own table. They need their own reviewed
  path (a pointer RPC, or a scoped reader role) before any profile without direct table
  access, such as #73's self-hosted profile, can serve #226.
- **Revoking `authenticated` changes nothing for #226 unless `SESSION_READS_TOKEN` is
  `authenticated`.** If it is `service_role`, the open surface is that broad key, which #226's
  own doc already says production cannot assume. Hence the gate failure above.
- Inside 96BS, closing the direct surface breaks only tests (row 12) and #59's Lane C
  (row 13). Row 14 needs the presence-probe fix regardless.

## Proposed rollout and rollback order (for review; nothing applied)

1. #226 pins the `SESSION_READS_TOKEN` role and moves rows 1 and 3 to the RPC behind a
   flag, with RPC parity tests against today's direct responses (fields, order, cursor).
2. A pointer and rollout read path for rows 4 and 5 is reviewed and landed.
3. This PR's migration revokes direct `SELECT` on `session_directory`, `_users` and
   `_machines` from `authenticated` (and from the `SESSION_READS_TOKEN` role if it is a
   dedicated reader), keeping the Worker RPC as the only directory read path.
   `SESSION_DIRECTORY_QUERIES` is retired or kept test-only.
4. Rollback: the down migration restores the column grant from `20261030020000`, and #226's
   flag returns to direct reads. Both steps are independent, and either order is safe
   while the RPC stays in place.
