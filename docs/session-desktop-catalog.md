# Scoped Desktop catalog metadata

The additive 20261105022000 migration exposes one claim-bound `session_directory_desktop_catalog(workspace,harness,session)` RPC to the existing search Worker role. It grants no table access and uses the existing JWT issuer/audience/tenant/role policy. The selected RHC catalog route serves only the audited Desktop metadata fields; it does not port unused firstPrompt/marker/commit-link enrichment or fan out to parent transcripts.

`modelsComplete:true` means the deduplicated union of complete catalog_models and171event_models, including a valid empty union. The old catalog writer silently retained only64models; the new writer records modelsComplete=false on overflow, rejected/changed strings or old writer input. An incomplete union refuses instead of acknowledging a partial array.

Parent/child IDs and only the needed childModel/childAgentName/childAgentType are stored as metadata. Real projected values are preserved; no guardian/model metadata is guessed from prompt text. The old500-edge cap can hide an incoming parent entirely, so the read RPC requires the workspace relationship index to be complete. The new writer explicitly records truncation/missing metadata; any unready live row blocks this readmodel. A source with >500outgoing edges needs a complete metadata representation before this gate can pass. This is an explicit readiness limit, not an empty-parent fallback.

Each catalog marker binds to the directory event epoch and catalog projection timestamp. Old/mixed writer output cannot reuse the prior readiness marker. Existing rows default unready; controlled complete-source reprojection is required after schema/code installation. Tombstones and hard deletes retain existing companion erasure semantics. The RPC refuses foreign claims, dirty/unready171metadata and stale/incomplete catalog markers; it returns authenticated absence only for a missing live logical row. It hashes the bounded returned metadata snapshot; RHC rechecks that fingerprint before responding.

The Supabase function ACL manifest, frozen event-trigger body/hash, worker grant verifier and migration sentinel are updated together. Rollbacks run 20261105031000 first (its rollback guard refuses with 55000 while any later migration is ledgered, restores the 20261105022000 RPC body and deletes its own ledger row), then 20261105022000 before 20261105020000 before 171 (after any later 20261105023000 rollback). Before the 20261105022000 rollback, disable selected metadata readers and retire code that writes the new columns; the down file is not an authorization to change production schema. No deployment, role creation or production access is included.

Validation: 6 new PGlite tests in `src/hoopdb/__tests__/session-desktop-catalog.test.ts` (actual SQL, worker role) and root TypeScript; 20261105031000 adds `src/hoopdb/__tests__/session-desktop-catalog-forget.test.ts` (dormant default, owner-only switch, forget/restore/purge marking, the tombstone-then-resurrect scenario, writer epoch, >500 refusal, the repair path across pages, finding 4, rollback/reapply) and its down/reapply and rollback-guard case in `migration-profile.test.ts`. The other controls are not in that file: existing list/catalog writer compatibility and the reverse-order up/down/up (20261105023000, then 20261105022000, 20261105020000, 20261104021000 down, reapplied in order) live in `src/hoopdb/__tests__/session-directory-list.test.ts`; the exact SECURITY DEFINER/ACL manifest and frozen trigger hash checks live in `src/hoopdb/__tests__/migration-profile.test.ts`. Omitting171event_models makes1model-union control fail; removing workspace edge readiness makes1parent-absence control fail. The separate RHC route has5newtests including actual caller shape, empty complete union, foreign/incorrect edges, changed fingerprint, absence and no-Neon controls. Independent review, applied schema/backfill, all production source capacity and the coordinating operator gates remain required.

## Forget tracking and reprojection (20261105031000)

Migration `20261105031000_desktop_catalog_forget_reproject.sql` closes the blockers that needed SQL. It is dormant on apply: an owner-only control row (`sessions.session_desktop_catalog_control.forget_tracking`, default false), an empty queue (`sessions.session_desktop_catalog_reproject`), one constant-default column (`session_directory.catalog_forgotten_child_edges`), triggers whose first operation reads the control row, and owner-only functions. Applying it creates no derived state.

- **Switch.** `sessions.set_session_desktop_catalog_forget_tracking(boolean)` (owner only, no grants) takes `session_directory` in SHARE mode so no tombstone, restore or catalog write straddles the flip. Enabling resets every `catalog_read_version` to 0 and empties the queue: forgets during a disabled interval were not tracked, so the catalog stays refused until a complete reprojection after enabling. While it is off the read RPC refuses (`0A000 forget_tracking_not_enabled`) and the repair page refuses (`55000`).
- **Forget.** A tombstone or hard delete of a session marks every live parent holding an edge to it `pending` in the queue (parent ids only; the erased child's id is never stored) and drops the session's own queue row. Its triggers sort before `session_directory_forget_catalog_on_*`, so the edges still exist. The work is one index lookup and one queue row per incoming edge the existing forget trigger deletes in the same statement: no workspace scan and no directory row lock, so it cannot deadlock with the writer. The read RPC treats a live pending parent like `catalog_relationships_complete=false`: the workspace refuses (`relationship_metadata_not_ready`) until that parent is reprojected. Pending is never permanent: a reprojection always settles it.
- **Writer.** The desktop writer (`writeDirectoryCatalog`) takes the event epoch its source read was fenced on (`expectedEpoch`) and writes nothing (`{ written: false, staleEpoch: true }`) when the row's `event_projection_epoch` has moved. It locks every named child row FOR SHARE in session-id order after the parent row, so a concurrent forget or restore of a child either committed before it read the child or waits and then re-queues the parent. When it drops an edge because the child is a tombstone it sets `catalog_forgotten_child_edges`; its completion trigger then keeps the parent as `watch` (otherwise it deletes the parent's queue row).
- **Restore or purge.** Restoring a tombstone (`deleted_at` back to NULL) or hard-deleting one makes every `watch` parent of that (org, workspace, harness) `pending` again, so the dropped edge comes back on reprojection. Without the child id this cannot be narrower; it touches only queue rows.
- **Fan-out.** The read RPC refuses (`0A000 relationship_fanout_exceeded`) when a session has more than 500 parents or 500 children, instead of returning a truncated list. `truncated` stays in the response and is always false.
- **Repair path.** `sessions.session_desktop_catalog_reproject_page(after_org, after_workspace, after_harness, after_session, limit)` (owner only, read-only, no row locks, at most 500 per page) lists live pending parents in "C" key order after an exclusive cursor. `reprojectPendingDesktopCatalogParents` (`src/hoopdb/session-desktop-catalog-reproject.ts`) pages it on the owner connection and calls an injected reprojector per parent with no transaction or lock held, so the reprojector may read canonical sources over the network. It returns the cursor to resume from; a parent whose reprojection fails stays pending and is retried by the next run from the start.
- `directoryCatalogFromProjection` no longer reports `modelsComplete:true` when a `session_catalog` row's `models` is not an array (missing or unparseable `models_json`) or holds a non-string; `incompleteReasons` records why (#182 contextual review, finding 4). The legacy writer ignores these fields, so its SQL and parameters are unchanged.

## Activation blockers (adversarial review 2026-11-05)

Closed by 20261105031000 (once applied and enabled): tombstone-then-resurrect (Medium), the writer epoch check (Low 3) and the >500 incoming parents truncation (Low 4); see the section above. Still open, so the catalog must not be served until it is resolved or explicitly accepted:

1. **One bad session blocks the whole workspace until its source changes.** A single session with >500 outgoing edges, an over-long or control-character child label, or an invalid relationship id records `catalog_relationships_complete=false`, and the workspace-wide edge-index check refuses every session of the workspace for as long as that source stays as it is. Reprojection does not clear it. (The forget/restore marks added by 20261105031000 do not have this problem: a reprojection always clears them.) Closing it needs per-edge readiness in the read model, a separate reviewed change.

### Writer switch: `SESSION_DESKTOP_CATALOG_ENABLED`

Flag off = pre-#182 writer; flag on = complete catalog with 20261105022000 columns. The search stage (`src/session-pipeline/search-index.ts`) picks its catalog writer with `directoryCatalogWriter` (`src/hoopdb/session-directory-catalog.ts`) from the session pipeline Lambda's `SESSION_DESKTOP_CATALOG_ENABLED`. Only the literal `"1"` turns it on; unset or any other value is off, with no error.

- **Off (default):** `writeLegacyDirectoryCatalog`, the writer as it was before #182 (0c12036, unchanged until a49219d^1). It writes the same columns, values and query shape: agent names, catalog models, project key and method, initial commit, originator, agent version, project id, repo, branch, the scalar agent and search text, `catalog_projected_at`, agent rows, and parent -> child edges (uid and child id only). It writes none of 20261105022000's columns (no `child_*` edge metadata, no `catalog_read_*`, no completeness flags) and runs on a schema without that migration.
- **On:** `writeDirectoryCatalog`, #182's complete desktop catalog writer, which needs 20261105022000 and records the readiness markers this read model checks.

`SEARCH_INDEX_ENABLED=1` alone must never select the desktop writer: the search stage is live in production and must keep writing exactly what it wrote before #182.

The stack (`stacks/aws/session-pipeline.ts`) always sets `SESSION_DESKTOP_CATALOG_ENABLED="0"` and refuses `transcriptStore.sessionPipeline.desktopCatalog: true` ("desktopCatalog requires the forget/reproject fix (migration 20261105031000) and its review; not wired yet"). The desktop writer needs the columns of both 20261105022000 and 20261105031000: with the flag on and either migration missing, every catalog write fails inside the search transaction (42703) and the messages retry to the DLQ.

Activation, in order. Each step that applies a migration, changes a role or deploys needs the owner's separate, explicit approval:

1. Land and review the 20261105031000 change (done when its PR merges) and resolve or explicitly accept the open blocker above.
2. **Apply 20261105022000 and 20261105031000 to production** with the migrator (in supabase event-trigger mode the regenerated `supabase/bootstrap/hoopdb_sessions_function_boundary_supabase.sql`, whose embedded manifest lists the 031000 functions, must be installed first, per runbooks/session-directory-search-worker-bootstrap.md), then **verify** them there: both ledger rows present (`upstream:20261105022000_session_desktop_catalog.sql`, `upstream:20261105031000_desktop_catalog_forget_reproject.sql`), both sentinels true, the post-migrate exact-ACL check clean, `forget_tracking` false and the queue empty. Do not flip `SESSION_DESKTOP_CATALOG_ENABLED` before both are applied and verified.
3. As the schema owner, `SELECT sessions.set_session_desktop_catalog_forget_tracking(true)`.
4. Lift the stack refusal and wire the env to `desktopCatalog` in a **separate reviewed PR**; this change keeps the refusal.
5. Deploy with the flag on, run a complete reprojection of every live session, then run the repair path until the page is empty, and only then let a reader call the RPC.
