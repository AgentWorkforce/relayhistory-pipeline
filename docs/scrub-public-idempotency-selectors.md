# Public idempotency selectors in tool input

Ruleset 9 preserves benign values of the exact case-insensitive `idempotency_key` identifier. This field selects a replay receipt; it is not an authentication credential. Version 7 consumed the whole assignment and hid a nested credential. Version 8 resumed scanning the value, but quoted multi-word tails and encoded separators could survive. Their source fixtures remain immutable failing witnesses.

Version 9 scans nested labelled credentials through the matching quote or end of the enclosing value, including literal JSON-style (`\u003d`, `\x3d`) and percent-encoded (`%3D`, `%3A`) colon/equal separators in either hex case and JSON escaping depths. These separators are recognized without decoding or rewriting the surrounding text. JSON and token-preserving record paths retain the public property's string boundary after decoding, including descendants. Assignment spans prevent segmentation from detaching a secret tail. Rescanning a scrubbed record is stable and preserves its enclosing structure. A label-like public value such as `retry-key:7` can therefore be redacted; plain public selectors stay byte-identical. Strict one-line `op://` references retain their existing exception.

There is no new default-off scrubber flag. This fixes an existing mandatory privacy boundary; newly sealed objects record version 9 and its manifest/corpus pins. Version metadata records what ran, not a runtime enablement approval. Existing create-only objects are not rewritten or retroactively repaired: a lost-create race retains the stored bytes and their original metadata.

Do not assume an older server refuses newer scrub markers. At the version-7 source, `ScrubMarkerSchema` accepts versions 1 through `0xffffffff`, and `keepStored` requires only a positive integer scrub version. Neither is a current-version ceiling. Rollback/adoption requires evidence for the actual consumer and image; metadata alone is not a fail-safe rollback gate. The buffered search-feed timestamp version band is unrelated to scrub ruleset numbers and stays separately gated.

The shared corpus includes nested assignment, quoted-tail, encoded-separator and direct/tool-record regressions. Frozen-witness tests pin historical bytes; `scrub-ruleset-version.test.ts` alone asserts the latest current version. The committed deterministic v7/v8-to-v9 differential checks marker non-re-emission, idempotence and benign public controls; it is bounded test evidence, not a proof for arbitrary input.

Desktop's Rust pin, lockstep/wrapper/retry-identity checks and the Cloud mirror each require their own matching version-9 source/corpus pins, review and qualification. Copying only the new corpus into an old ruleset is insufficient. No Desktop or Cloud adoption follows from this source change. Tool-use display classification remains a separate projection concern.
