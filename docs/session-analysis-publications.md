# Dormant full v1 analysis cache prerequisite

Status: source snapshot, bounded codec, pointer publication and demand lease ledger are implemented. Runtime scheduler/hint/backfill wiring and actual bounded workerd proof are pending. This document does not authorize a deploy, credential capture, schema apply, grant or enablement.

The Node publisher calls the actual readonly `read_session_analysis_v1` projection with 0031 overriding 0024. Public request/job IDs, status/history, nested brief fields and result JSON are retained. The virtual v1 job ID remains the SQL-projected ID. Workspace safety uses real request brief_job_id/analysis_job_id contributors rather than looking up that virtual ID in the physical job table. All session evidence must attest one selected workspace/source; requests from another workspace are removed. Missing/foreign contributor evidence masks result and marks that analysis failed with workspace_scope_unverified. An analysis explicitly omitted by 0031's superseded rule is not a contributor to the retained brief.

A source adapter uses REPEATABLE READ READ ONLY with a server statement timeout and separately read-only credentials. It emits UTC six-fraction snapshotAt and a SHA of the source MVCC snapshot ID. The exact canonical public envelope SHA is computed with shared analysisSnapshotJson; analysisGenerationJson fixes identity/source property ordering across PostgreSQL JSONB and RPC serialization. Generation binds payload SHA, source epoch/fingerprint, source snapshot time and snapshot ID. The real SQL not_found outcome is stored explicitly, never inferred from an empty exporter.

Every immutable object uses the existing canonical graph limits: roots/nodes/pages <=256KiB, segments <=64KiB, fanout128/depth4. The wrapper is session-analysis-index v1 / canonical-analysis-graph-v1. Two raw tables hold private identity fields, numeric ordinal and untouched public payload. A table-specific numeric ordinal comparator preserves the SQL array subsequence order. Arbitrary large result objects use exact JSON blob segments; no public field is interpreted as a codec sentinel. Aggregate canonical envelope has an explicit64MiB refusal ceiling, which is not a claim that128MiB workerd can assemble that amount. Actual large-result and total-response memory must be measured before activation.

Supabase stores pointer metadata and demand metadata only. Publication requires a live non-tombstoned canonical directory, the complete current replay source epoch/fingerprint, a current unexpired backend lease nonce, immutable verified object refs, and source snapshotAt strictly newer than the prior publication. Equal timestamps allow only an exact idempotent retry; divergence refuses. Source snapshots older than120seconds or over30seconds in the future refuse. The read RPC returns current=false when missing/stale/source-invalid, and authenticates with the existing signed search-worker tenant/workspace policy. Claim timestamps use the same UTC6 Z serialization as the immutable wrapper. Consumer rechecks the exact original wrapper pointer/source/snapshot acknowledgement after hydration; no Neon fallback.

The narrow request_session_analysis_cache(workspace,harness,session) RPC is intentionally a permitted read-role side effect: it collapses demand for an already live canonical identity into one wakeup row. It grants no table access. Repeated calls are debounced30seconds and keep a5minute active demand window. The worker claims one90second random-nonce lease, heartbeats every20seconds, publishes through the same lease-bound CAS, then schedules the next refresh30seconds later. Expired/replaced/source-invalid leases cannot publish or finish. Erasure invalidates heartbeat/publication/finish; claim removes blocked wakeups. Failure stores only a bounded code and retries with a capped delay. The30second cadence is a target until runtime scheduler load/latency is measured, not a guarantee from these unit checks.

Backfill and source-change hints must enqueue identities and use this same leased runner. A one-off helper or raw S3 event hook alone is insufficient: analysis job/request transitions do not necessarily rewrite raw S3. Required remaining wiring includes a reliable all-transition legacy outbox hint, default-off scheduled runtime, bounded reconciliation/backfill with durable continuation, and measured publisher demand/load. No global per-read or global30second Neon scan is permitted.

New source-read credentials, Supabase backend RPC access, normalized-prefix scoped Put/Get and applicable KMS permissions, exact migration/ACL/bootstrap union and deployed reader/publisher versions need operator capture. Current Get-only raw credentials do not prove writes or new-prefix reads. Keys stay under the first current physical raw-hash normalized prefix so existing erasure/orphan rules apply; same-anchor generation retention/GC remains a separate activation dependency.

Offline tests vendor only the exact0031 projection and0024 read function as a SQL oracle from RHC9ff3a285cf2d7ac617ad4a2a59ffc6931a60fecb. Production code calls that source function and does not fork it. The proof script uses only synthetic PGlite and FS objects; no real credential is needed.
