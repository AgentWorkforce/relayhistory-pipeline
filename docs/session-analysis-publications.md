The narrow request_session_analysis_cache(workspace,harness,session) RPC is intentionally a permitted read-role side effect: it collapses demand for an already live canonical identity into one wakeup row. It grants no table access. Repeated calls are debounced 30 seconds and keep a 5 minute active demand window. The worker claims one 90 second random-nonce lease, heartbeats every 20 seconds, publishes through the same lease-bound CAS, then schedules the next refresh 30 seconds later. Expired/replaced/source-invalid leases cannot publish or finish. Erasure invalidates heartbeat/publication/finish; claim removes blocked wakeups. Failure stores only a bounded code and retries with a capped delay. The 30 second cadence is a target until runtime scheduler load/latency is measured, not a guarantee from these unit checks.
