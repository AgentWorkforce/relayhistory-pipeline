# Native briefs from JSONL transcripts

The native brief worker can read an existing authenticated JSONL transcript pointer without changing its format, objects, or revision. Its separate transcript reader uses the same tenant-bound live pointer query and org-derived Locker configuration as the canonical record-stream reader. Public canonical record-stream routes remain ndjson-only.

Before reading messages, the worker verifies the complete pointer set and each manifest's admitted user, tenant, physical/logical session and machine identity, key prefix, format, revision, content hash chain, optional etag and scrub marker. It validates the full manifest hash chain, then reads only the manifest library's live epoch/continuation selection. Superseded rewrite/truncation content is not fetched or summarized. It checks every selected live chunk's size and digest, the scrubbed chunk’s raw digest and declared raw size, and decodes UTF8/JSON strictly. JSON records and UTF8 characters may cross chunk boundaries. Malformed records are refused rather than skipped. A mixed JSONL/ndjson pointer set is refused rather than partially summarized.

The existing bounds remain: fewer than 64 pointers, 16 MiB for source/stored bytes and 100,000 records. Actual decoded bytes and records are bounded independently of declarations; counts and byte bounds apply to that complete selected live stream. The existing brief normalizer, maximum of 4,000 messages and existing text budget still select only user/assistant text, excluding meta, sidechain, tool output and thinking blocks. All manifests must be scrubbed. There is no legacy-reader fallback or format relabelling.

The full pointer generation is checked again after object reads. The native worker retains its existing physical-to-logical scope checks before/after input collection, publication revision and alias fences, model admission limits and read-RPC freshness checks. This adds no schema migration, table grants or provider credentials. Live deployment and genuine provider qualification remain separate operator actions.

Only a native canonical-input worker’s normal sweep may re-arm an unchanged failed `canonical_input_refused` attempt when every current live physical pointer is JSONL and has a manifest. An existing wakeup or lease is retained. The recovery goes through the ordinary input checks, throttle, daily caps and model admission; it does not reset attempt accounting. New JSONL refusals use `canonical_jsonl_input_refused`, so a failed recovery cannot match the historical-error predicate repeatedly. Other errors, ndjson/mixed sources and unselected workspaces are unchanged. This recovery does not issue an immediate model call or require an operator to rewrite rows or resynchronize stored data.
